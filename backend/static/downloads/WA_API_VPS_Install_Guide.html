Deploy WA_API without touching your other projects

A short, isolation-first recipe for wa.animitra.in. Uses only unused resources — your existing services on ports 8001, 8002, 8003 stay untouched.

domain · wa.animitra.in backend · :8004 sidecar · :3005 folder · /opt/wa_api db · wa_api_db user · wa_api

Isolation guarantees

Every resource this guide creates is namespaced with the wa_api prefix so it cannot collide with anything you already run: /opt/wa_api user wa_api db wa_api_db supervisor wa_api_backend/wa_api_sidecar logs /var/log/wa_api nginx wa_api.conf ports 8004/3005

0. Pre-flight — 30-second collision check

Run these on your VPS before anything else. All four MUST print nothing (or explicit "free"):

ss -tlnp | grep -E ':(8004|3005)\s' || echo "ports free"
id wa_api 2>/dev/null || echo "user free"
test -e /opt/wa_api && echo "FOLDER EXISTS — pick a different path" || echo "folder free"
grep -rli "wa.animitra.in" /etc/nginx/ || echo "nginx free"

If any check shows a collision

Either free the resource, or edit the values below to unique ones (e.g. /opt/wa_api2, port 8014, user wa_api2). The rest of the guide works after a simple find-replace.

1. Install runtime (one paste)

Adds Python 3.11, Node 20, Mongo 7, nginx, supervisor. Safe to re-run — apt install is a no-op if the package is already present.

sudo apt update && sudo apt install -y build-essential git curl ca-certificates \
     gnupg lsb-release software-properties-common ufw unzip nginx certbot \
     python3-certbot-nginx supervisor

sudo add-apt-repository ppa:deadsnakes/ppa -y && sudo apt update
sudo apt install -y python3.11 python3.11-venv python3.11-dev

curl -fsSL https://deb.nodesource.com/setup_20.x | sudo bash -
sudo apt install -y nodejs && sudo npm install -g yarn

# MongoDB 7 — skip if already installed on this VPS
if ! command -v mongod >/dev/null; then
  curl -fsSL https://www.mongodb.org/static/pgp/server-7.0.asc \
       | sudo gpg -o /usr/share/keyrings/mongodb-server-7.0.gpg --dearmor
  echo "deb [signed-by=/usr/share/keyrings/mongodb-server-7.0.gpg] https://repo.mongodb.org/apt/ubuntu $(lsb_release -sc)/mongodb-org/7.0 multiverse" \
       | sudo tee /etc/apt/sources.list.d/mongodb-org-7.0.list
  sudo apt update && sudo apt install -y mongodb-org
  sudo systemctl enable --now mongod
fi

sudo adduser --disabled-password --gecos "" wa_api
sudo mkdir -p /opt/wa_api /var/log/wa_api
sudo chown -R wa_api:wa_api /opt/wa_api /var/log/wa_api

cd /opt/wa_api/backend

cat > .env <<EOF
MONGO_URL="mongodb://127.0.0.1:27017"
DB_NAME="wa_api_db"
JWT_SECRET="$JWT"
JWT_ACCESS_MINUTES=60
JWT_REFRESH_DAYS=14

grep SIDECAR_TOKEN .env    # copy this value — you need it in step below

wa-sidecar/.env

cd /opt/wa_api/wa-sidecar
cat > .env <<EOF
PORT=3005

frontend/.env

cd /opt/wa_api/frontend
cat > .env <<'EOF'

4. Install deps, build UI, register both services

# Python
cd /opt/wa_api/backend
python3.11 -m venv .venv && source .venv/bin/activate
pip install --upgrade pip wheel && pip install -r requirements.txt
deactivate

# Node (sidecar + frontend)
cd /opt/wa_api/wa-sidecar && yarn install --production=false
cd /opt/wa_api/frontend   && yarn install && yarn build

exit  # leave the wa_api shell — need sudo again

Register two supervisor programs. Namespaced with wa_api_ so they show up separately from your other projects:

sudo tee /etc/supervisor/conf.d/wa_api_backend.conf >/dev/null <<'EOF'
[program:wa_api_backend]
command=/opt/wa_api/backend/.venv/bin/uvicorn server:app --host 127.0.0.1 --port 8004 --workers 2
directory=/opt/wa_api/backend
user=wa_api
autostart=true
autorestart=true
stopasgroup=true
killasgroup=true
stdout_logfile=/var/log/wa_api/backend.out.log
stderr_logfile=/var/log/wa_api/backend.err.log
environment=PATH="/opt/wa_api/backend/.venv/bin:/usr/bin:/bin"
EOF

sudo tee /etc/supervisor/conf.d/wa_api_sidecar.conf >/dev/null <<'EOF'
[program:wa_api_sidecar]
command=/usr/bin/node index.js
directory=/opt/wa_api/wa-sidecar
user=wa_api
autostart=true
autorestart=true
stopasgroup=true
killasgroup=true
stdout_logfile=/var/log/wa_api/sidecar.out.log
stderr_logfile=/var/log/wa_api/sidecar.err.log
EOF

sudo supervisorctl reread && sudo supervisorctl update
sudo supervisorctl status wa_api_backend wa_api_sidecar
# both must read RUNNING

5. Nginx — add-only, never touches other sites

Isolation policy

We drop a new file into sites-available and enable ONLY it. Your other project configs stay linked and untouched.
sudo tee /etc/nginx/sites-available/wa_api.conf >/dev/null <<'EOF'
server {
    listen 80;
    server_name wa.animitra.in;
    root /opt/wa_api/frontend/build;
    index index.html;

    location /api/ {
        proxy_pass         http://127.0.0.1:8004;
        proxy_http_version 1.1;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
        proxy_set_header   Upgrade           $http_upgrade;
        proxy_set_header   Connection        "upgrade";
        proxy_read_timeout 3600;
        client_max_body_size 60m;
    }

    location / { try_files $uri /index.html; }

    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff2?)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
}
EOF

sudo ln -sf /etc/nginx/sites-available/wa_api.conf /etc/nginx/sites-enabled/wa_api.conf
sudo nginx -t && sudo systemctl reload nginx

If wa.animitra.in already served another site

Another config still owns the server_name. Find and remove ONLY it — leave all other files alone: 
sudo grep -rli "wa.animitra.in" /etc/nginx/     # list configs claiming the domain
# For each file that is NOT wa_api.conf, either unlink from sites-enabled/, or
# open it and delete the specific `server { … server_name wa.animitra.in; … }` block.
sudo nginx -t && sudo systemctl reload nginx

6. HTTPS + verify — 3 checks before certbot

# a) nginx will really serve WA_API for this domain
sudo nginx -T | grep -B1 -A20 "server_name wa.animitra.in;" | grep -E "root|proxy_pass"
# Expect:  root /opt/wa_api/frontend/build;   AND   proxy_pass http://127.0.0.1:8004;

# b) plain-HTTP landing page = WA_API
curl -s http://wa.animitra.in/ | grep -o "WA_API" | head -1     # → WA_API

# c) /api is proxied to FastAPI (JSON, not HTML)
curl -s http://wa.animitra.in/api/health                        # → {"ok":true,...}

If all three pass, issue the certificate:

sudo certbot --nginx -d wa.animitra.in \
             --agree-tos -m admin@animitra.in \
             --redirect --non-interactive

Now open https://wa.animitra.in/login → sign in as admin@animitra.in / ChangeMeAfterFirstLogin! → Sidebar → Password to change it → SMTP to configure email → User dashboard → Sessions → NEW SESSION to scan the QR.

7. Troubleshooting

SymptomFix
Domain shows a DIFFERENT project (old CRM/installer/etc.)Old nginx block owns the server_name. See §5 warning above.
HTTPS still shows old site after nginx fixsudo certbot delete --cert-name wa.animitra.in then re-run the certbot command in §6.
502 from nginxBackend crashed. sudo supervisorctl status wa_api_backend, sudo tail -f /var/log/wa_api/backend.err.log.
Sidecar won't startPort already used — sudo ss -tlnp | grep 3005. Or SIDECAR_TOKEN mismatch between backend/.env and wa-sidecar/.env.

CRM: /api/v1/sessions/<slug>/status shows connected: falseCheck sidecar_reachable. If false, backend can't reach sidecar — check WA_SIDECAR_URL + supervisor.

8. Upgrade & uninstall (clean rollback)

Upgrade (deploy new code)

sudo -iu wa_api
cd /opt/wa_api && git pull
cd backend && source .venv/bin/activate && pip install -r requirements.txt && deactivate
cd ../wa-sidecar && yarn install --production=false
cd ../frontend  && yarn install && yarn build
exit
sudo supervisorctl restart wa_api_backend wa_api_sidecar
sudo systemctl reload nginx

Uninstall (no trace, other projects untouched)

sudo supervisorctl stop wa_api_backend wa_api_sidecar
sudo rm -f /etc/supervisor/conf.d/wa_api_backend.conf /etc/supervisor/conf.d/wa_api_sidecar.conf
sudo supervisorctl reread && sudo supervisorctl update
sudo rm -f /etc/nginx/sites-enabled/wa_api.conf /etc/nginx/sites-available/wa_api.conf
sudo systemctl reload nginx
sudo certbot delete --cert-name wa.animitra.in || true
sudo rm -rf /opt/wa_api /var/log/wa_api
mongosh wa_api_db --quiet --eval "db.dropDatabase()" || true
sudo deluser wa_api || true
